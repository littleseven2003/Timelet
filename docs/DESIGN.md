# Timelet（时屿）产品设计与开发大纲

> 本文档是 Timelet 的产品设计与开发路线总纲。开发过程中的功能取舍、界面方案、里程碑推进均以本文档为准；与本文档不一致的改动需先经项目所有者确认。工程规范（Git、提交、协作机制）见项目根目录的协作规范文档。

---

## 1. 产品定位

**Timelet（时屿）** 是一款常驻系统托盘的倒计时工具：在 macOS 菜单栏 / Windows 任务栏显示一个小图标，点击后在图标旁弹出一个小面板，展示用户自定义的各类倒计时与正计时条目；通过右键菜单可打开配置窗口，对条目进行增删改。

- **名称释义**："时"指时间，"屿"指时间之海中的一座座小岛——每个倒计时条目都是时间线上被标记的一座岛屿。
- **一句话定位**：把重要的日子放在手边，随时看一眼还剩多久。

### 参考产品

| 产品 | 借鉴点 |
|------|--------|
| 倒数日（Days Matter） | 条目模型：名称 + 目标日期，倒计时/正计时双模式 |
| One Thing | 菜单栏轻量展示、极简交互 |
| iBar / 各类菜单栏日历 | 托盘弹窗的定位与显隐交互 |

## 2. 目标平台与运行形态

- **macOS 12+**：菜单栏图标；左键点击在图标正下方弹出面板（popover 式），右键显示托盘菜单。
- **Windows 10/11**：任务栏托盘图标；左键点击在任务栏图标上方弹出面板，右键显示托盘菜单。
- 应用无常驻主窗口，仅"弹出面板"与"配置窗口"两类窗口。
- 支持开机自启（设置为可选项，默认关闭）。

## 3. 功能大纲

### 3.1 核心概念：条目（Entry）

所有展示内容以"条目"为基本单位，每个条目包含：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 唯一标识（UUID） |
| name | string | 条目名称，如"项目上线"、"已坚持晨跑" |
| type | `countdown` \| `elapsed` | 倒计时（距目标日）/ 正计时（自起始日已过） |
| date | string (ISO 日期) | 目标日期（倒计时）或起始日期（正计时） |
| color | string | 条目标签色（预设色板中选取） |
| pinned | boolean | 是否置顶显示 |
| createdAt / updatedAt | string | 创建/更新时间 |

### 3.2 弹出面板（主视图）

- 列表展示全部条目：名称 + 剩余天数（倒计时）或已过天数（正计时）。
- 倒计时条目按剩余天数升序排列；置顶条目优先；已过期条目显示"已过期 N 天"并置底（是否显示可配置）。
- 面板顶部显示当天日期与星期。
- 面板宽约 320px，高度随条目数量自适应，最多展示 8 条后内部滚动。
- 点击面板外部自动收起；再次点击托盘图标可再次打开。

### 3.3 配置窗口

- 条目列表管理页：增、删、改、拖拽排序、置顶。
- 条目编辑表单：名称、类型（倒计时/正计时）、日期选择器、颜色。
- 通用设置页：
  - 开机自启开关；
  - 已过期条目是否显示；
  - 托盘图标上是否直接显示最紧要条目的天数（Windows 支持图标叠字，macOS 保持纯图标，首版从简，可仅文字菜单栏标题可选）；
  - 关于页（版本、开源地址、许可证）。

### 3.4 首版（MVP，v0.1）范围

**包含：**

1. 托盘图标 + 左键弹出面板 + 右键菜单（打开配置 / 退出）；
2. 条目模型：日期倒计时 + 正计时两种类型；
3. 配置窗口的条目增删改与置顶；
4. 本地数据持久化（JSON 文件），重启后数据保留；
5. 中文界面（结构上保留双语切换能力）。

**不包含（明确排除）：**

- 循环/重复倒计时（如下班倒计时、每周例会）；
- 到期提醒与系统通知；
- 云同步、账号体系、多设备；
- 数据导入导出；
- 主题切换（首版跟随系统深浅色做基础适配即可）。

### 3.5 后续路线图（暂定，逐版确认后实施）

| 版本 | 内容 |
|------|------|
| v0.2 | 循环倒计时条目（每天/每周/每月/每年重复）；条目分组 |
| v0.3 | 到期提醒（系统通知，支持提前 N 天提醒）；开机自启完善 |
| v0.4 | 数据导入导出；英文界面（启用预留的 i18n 结构） |
| v1.0 | 双平台安装包经 GitHub Releases 发布；README、使用说明、图标打磨 |

## 4. 界面设计要点

- **整体风格**：安静、轻量、中性色为主；条目颜色仅用于左侧色条与天数强调，不做大面积色块。
- **弹出面板**：无边框窗口，圆角与投影，跟随系统深浅色；macOS 上带半透明材质感（vibrancy 可选）。
- **配置窗口**：常规桌面窗口（约 640×480），左侧"条目管理 / 通用设置 / 关于"三栏导航，右侧内容区。
- **空状态**：无条目时显示引导文案"在设置中添加你的第一个倒计时"+ 跳转按钮。

## 5. 技术架构

```
┌────────────────────────────────────────────┐
│ 前端（Vue 3 + TS）                          │
│  ├─ 面板视图（弹出面板，小窗口）              │
│  ├─ 配置视图（配置窗口）                     │
│  └─ i18n（zh-CN 首版，预留 en-US）           │
├────────────────────────────────────────────┤
│ Tauri 桥接层（invoke / event）              │
│  ├─ entry_list / entry_save / entry_delete │
│  └─ settings_get / settings_set            │
├────────────────────────────────────────────┤
│ Rust 侧（src-tauri）                       │
│  ├─ 托盘图标与菜单（双平台行为差异封装）      │
│  ├─ 窗口管理（弹出定位、失焦收起）           │
│  └─ 存储模块（JSON 文件读写，原子写入）       │
└────────────────────────────────────────────┘
```

关键决策：

1. **存储**：本地 JSON 文件，位于系统标准应用数据目录（macOS `~/Library/Application Support/`，Windows `%APPDATA%`），写入采用"写临时文件 + 原子替换"避免损坏。
2. **窗口定位**：弹出面板显示前，通过托盘图标在屏幕上的坐标计算窗口位置（macOS 在图标下方、Windows 在任务栏上方），差异封装在 Rust 侧统一函数内。
3. **收起行为**：监听窗口失焦事件自动隐藏面板，两个平台行为一致。
4. **数据倒计时计算**：前端按本地时区计算剩余/已过天数，按自然日（非 24 小时制）计算，与"倒数日"类产品习惯一致。

## 6. 里程碑计划

每个里程碑对应一组功能分支，完成后合并进 `main` 并打 tag。

| 里程碑 | 内容 | 交付判据 |
|--------|------|----------|
| M0 脚手架 | 初始化仓库、.gitignore、LICENSE（GPL-3.0）、Tauri 2 + Vue 3 + TS 项目骨架、i18n 目录结构 | `pnpm tauri dev` 可运行默认窗口 |
| M1 托盘与面板 | 托盘图标、右键菜单、左键弹出面板、双平台窗口定位、失焦收起 | 空面板可正常弹出收起 |
| M2 条目与持久化 | 条目数据模型、JSON 存储模块、配置窗口（增删改/置顶/排序）、面板列表渲染 | 断言 1：添加条目后重启数据仍在 |
| M3 正计时与打磨 | 正计时类型、空状态、深浅色适配、过期条目处理、图标资源 | MVP 功能全部可用 |
| M4 双平台构建 | macOS 本地打包验证；Windows 打包方案确定（本机或后续 CI） | 两个平台均产出可安装包 |
| M5 发布准备 | README、版本号 v0.1、后续 GitHub Releases 与远程构建流程规划（暂不实施） | 具备发布条件，发布动作另行确认 |

## 7. 风险与注意事项

- **Windows 弹窗定位**：任务栏可能在屏幕四边，托盘图标坐标获取方式与 macOS 不同，M1 中预留手动测试项。
- **macOS 签名**：未签名应用首次打开需右键放行；正式分发是否申请 Apple Developer 签名，在 M5 前另行确认。
- **自然日计算**：跨时区/夏令时场景以"本地日历日"为准，避免出现"差一天"的观感问题。
- **数据格式演进**：0.x 阶段 JSON 结构可能调整，存储模块需保留版本字段（`schemaVersion`）以便后续迁移。

# 第一部分：产品定义

## 1. 产品定位

**Timelet（时屿）** 是一款常驻系统托盘的倒计时工具：在 macOS 菜单栏 / Windows 任务栏显示一个小图标，点击后在图标旁弹出一个小面板，展示用户自定义的各类倒计时与正计时条目；通过右键菜单可打开配置窗口，对条目进行增删改。

- **一句话定位**：把重要的日子安静地放在菜单栏，让用户随时知道"还有多久""已经多久""何时该做"。
- **名称释义**："时"指时间，"屿"指时间之海中的一座座小岛——每个倒计时条目都是时间线上被标记的一座岛屿。
- **产品类型**：轻量化倒数日 / 正数日 / 提醒工具，以菜单栏为主要日常入口，以主窗口为管理入口。

时屿不是一个完整日历，也不是任务管理器。它只承担一件事：把少量真正重要的时间节点，以最轻的方式留在用户视线附近。

### 产品气质

- **轻**：不打断工作，不要求频繁维护，不把简单需求复杂化。
- **静**：视觉克制、提醒适度，平时退居背景，需要时立即可见。
- **清**：时间状态一眼可读，类型、日期和下一步操作都明确。
- **准**：相对时间与确切日期同时可信，提醒状态始终可确认。
- **暖**：重要日期往往承载关系、记忆与期待，文案应有人情味，但不过度抒情。

### 设计目标

1. 用户点击菜单栏图标后，约 3 秒内找到最关心的条目和剩余时间。
2. 新建普通条目时，只填写标题、类型、日期三个核心信息即可完成。
3. 倒数日、正数日与提醒在视觉上容易区分，但仍属于同一套设计系统。
4. "时"与"屿"的意象进入信息结构、图形和动效，而不是成为表面装饰。
5. 即使用户完全不了解品牌意象，也能自然理解并高效使用。

### 明确边界

时屿不以复杂日程排布、项目协作、社交分享、重型统计或持续打卡为核心。它不与系统日历争夺"全部时间"，而是管理用户主动挑选出来的"重要时间"。

### 参考产品

| 产品                      | 借鉴点                                                     |
| ------------------------- | ---------------------------------------------------------- |
| 倒数日（Days Matter）     | 条目模型：名称 + 目标日期，倒计时/正计时双模式             |
| One Thing                 | 菜单栏轻量展示、极简交互                                   |
| iBar / 各类菜单栏日历     | 托盘弹窗的定位与显隐交互                                   |
| LikeDay                   | 大数字卡片展示、置顶、分类                                 |
| Reminder（lentikr/ybhgl） | 分组与标签、JSON 备份恢复、卡片/列表双布局、搜索过滤、农历 |
| Count Day（count-day）    | 节假日/调休识别的工作日倒计时、纯黑 OLED 主题、智能提示语  |

## 2. 核心意象与产品隐喻

### 2.1 "时"：方向、距离与节律

"时"不只是一枚钟表，更重要的是时间相对于某个节点的关系：

- 倒数日是**向节点靠近**；
- 正数日是**从节点向外延伸**；
- 提醒是**在时间线上被点亮的瞬间**（规划，见 4.6）；
- 周期提醒是**反复抵达的节律**。

因此，界面中的时间表达应优先使用"方向、距离、进度和刻度"，而不是到处放置钟表图案。

### 2.2 "屿"：独立、承载与聚合

每一个条目都像一座小岛：边界清楚、彼此独立，并承载一件重要的事。多个条目共同构成用户自己的"时间群岛"。

| 意象        | 产品含义       | 设计表达                           |
| ----------- | -------------- | ---------------------------------- |
| 一座岛      | 一个时间条目   | 独立但轻薄的条目单元               |
| 岛的轮廓    | 条目的边界     | 柔和圆角、清楚分组、不过度描边     |
| 岛群        | 多个相关条目   | 可用"岛群 · 分组"作标题（规划）    |
| 水面        | 安静的背景环境 | 大量留白、低对比背景、清透层级     |
| 潮汐        | 时间逐渐靠近   | 进度、状态变化与克制动效           |
| 灯塔 / 信标 | 需要注意的时刻 | 提醒点、状态标记、通知反馈（规划） |

### 2.3 融合原则：语义优先，装饰退后

- 不把主界面画成海岛地图，不使用大面积海浪、沙滩、椰树等插画。
- 不用晦涩的诗意词替代常用功能名称。界面写"新建条目""分组""归档"，而不是强迫用户理解"造岛""岛群""沉岛"。
- 品牌语言主要通过开放圆弧、低矮曲线、留白、清透颜色和微小的"浮现"动效体现。
- 品牌化词汇可用于视图、分区标题、欢迎页与空状态；核心操作始终直接明确。

### 2.4 品牌化命名的使用层级

"时""屿"相关词汇可以直接成为视图、分区或内容标题，采用"**意象标题 + 清晰上下文**"的方式：标题负责气质，条目内容或辅助说明负责解释。

| 品牌化标题 | 推荐含义                     | 建议出现位置                 | 状态                    |
| ---------- | ---------------------------- | ---------------------------- | ----------------------- |
| **此时**   | 今天、已到期和眼下需处理内容 | 菜单栏首个分区、主窗口今日区 | 规划（v0.2+，配合分组） |
| **将至**   | 即将到来的倒数日与提醒       | 菜单栏第二分区、未来列表     | 规划                    |
| **历时**   | 正在持续累积的正数日         | 正数日分区                   | 规划                    |
| **时线**   | 按时间顺序浏览全部条目       | 主窗口可选视图               | 规划                    |
| **岛群**   | 用户创建的条目分组           | 侧栏分组区标题               | 规划（v0.2 分组）       |
| **近屿**   | 置顶或近期最关注的少量条目   | 首页摘要或菜单栏精选区       | 规划                    |
| **远屿**   | 已归档但仍可找回的内容       | 归档空状态或说明文案         | 规划                    |

操作按钮不意象化：继续使用"新建条目、完成、稍后提醒、归档、删除、设置"等明确名称。内容标题富有品牌性，操作始终保持可预测。

## 3. 目标平台与产品结构

### 3.1 平台形态

- **macOS 12+**：菜单栏图标；左键点击在图标正下方弹出面板（popover 式），右键显示托盘菜单。
- **Windows 10/11**：任务栏托盘图标；左键点击在任务栏图标上方弹出面板，右键显示托盘菜单。
- 应用无常驻主窗口，仅"弹出面板"与"配置窗口"两类窗口。
- 支持开机自启（设置为可选项，默认关闭；M3 已实装）。

### 3.2 使用层级

```text
菜单栏缩略图
    ↓ 点击
快捷面板：查看当前条目、快速操作、快速新增
    ↓ 需要集中管理时
主窗口：全部条目、筛选搜索、新建编辑、归档与设置
```

- **菜单栏是"近岸"**：承载高频、短时、无需思考的操作——看一眼、快速新增、打开主界面。内容有限但始终可达。
- **主窗口是"群岛全景"**：集中管理全部条目、理解时间分布和修改配置。可以展示更多上下文，但保持单一主任务，不演变成复杂仪表盘。
- **设置是"水面之下"**：低频内容，独立于日常列表，不应让配置项长期占据主界面。

# 第二部分：功能设计

## 4. 功能大纲

### 4.1 核心概念：条目（Entry）

所有展示内容以"条目"为基本单位，用户只需理解一种对象，再通过类型决定它如何显示和提醒。

#### 类型

| 类型   | 用户问题   | 主显示形式    | 典型场景               | 状态      |
| ------ | ---------- | ------------- | ---------------------- | --------- |
| 倒数日 | 还有多久？ | `剩余 18 天`  | 节日、旅行、考试、生日 | 已实装    |
| 正数日 | 已经多久？ | `已过 328 天` | 纪念日、习惯起点、入职 | 已实装    |
| 提醒   | 何时该做？ | `今天 18:30`  | 喝药、缴费、预约、周期 | 规划 v0.3 |

#### 字段

| 字段                  | 类型                     | 说明                                                                                            |
| --------------------- | ------------------------ | ----------------------------------------------------------------------------------------------- |
| id                    | string                   | 唯一标识（UUID）                                                                                |
| name                  | string                   | 条目名称，如"项目上线"、"已坚持晨跑"                                                            |
| type                  | `countdown` \| `elapsed` | 倒计时（距目标日）/ 正计时（自起始日已过）                                                      |
| date                  | string (ISO 日期)        | 目标日期（倒计时）或起始日期（正计时）                                                          |
| time                  | string? (HH:mm)          | 可选时刻；带时刻条目按小时/分钟精度计算展示                                                     |
| repeat                | string?                  | 循环规则（daily 每天 / workday 工作日），仅带时刻条目生效（M3 已实装；每周/每月/每年规划 v0.2） |
| displayUnit           | string?                  | 展示单位（天/周/月/年），缺失按天                                                               |
| color                 | string                   | 条目标签色（预设色板或自定义取色）                                                              |
| note                  | string?                  | 选填备注，面板悬停与缩略详情中展示                                                              |
| pinned                | boolean                  | 是否置顶显示                                                                                    |
| sortIndex             | number?                  | 手动排序值（拖拽后生成）                                                                        |
| createdAt / updatedAt | string                   | 创建/更新时间                                                                                   |

字段层级遵循渐进式展开：标题、类型、日期是必填核心；时刻、循环、单位、颜色、置顶、备注按需出现在对应区域或「更多选项」中（备注与置顶常显于外观区）。

### 4.2 条目状态

每个条目除类型外还具有时间状态，状态决定排序、强调程度与可用操作：

- **平常**：距离较远，保持低视觉权重（已实装：默认样式）；
- **临近**：进入关注区间（如未来 7 天）——规划 v0.2（配合面板进度展示）；
- **今天**：强调确切时间——已实装（「就是今天」文案）；
- **已过期**：明确展示过期时长——已实装（是否显示可配置）；
- **持续计数**：正数日自然增长，不显示"过期"——已实装；
- **已完成 / 已归档**：离开默认视图，可搜索和恢复——规划（归档 v0.2+）。

"临近"区间可配置，但默认值应足够合理，避免用户首次使用就必须设置。

### 4.3 排序与组织

当前实现：置顶优先；未过期倒计时按截止时间升序；正计时按起始日期升序；已过期倒计时置底；用户手动拖拽后按手动顺序（置顶仍优先）。

目标排序原则（随分组/归档逐步对齐）："此刻最需要注意什么"优先于创建时间：今天与已到期提醒 → 置顶条目 → 即将发生的倒数日 → 正数日与较远条目 → 已完成与归档。

用户可按类型、分组、日期或置顶状态筛选（规划 v0.2）；搜索覆盖标题、备注和分组（规划）。分组属于可选能力，不在初次使用时强制出现。

### 4.4 弹出面板（主视图）

- 列表展示全部条目：名称 + 剩余天数（倒计时）或已过天数（正计时）。
- 倒计时条目按剩余天数升序排列；置顶条目优先；已过期条目显示"已过期 N 天"并置底（是否显示可配置）。
- 面板顶部显示当天日期与星期。
- 面板宽约 320px，高度随条目数量自适应，最多展示 8 条后内部滚动。
- 点击面板外部自动收起；再次点击托盘图标可再次打开。
- 面板右键菜单：条目上为「编辑详情 / 打开主界面」，空白处为「打开主界面」；托盘右键菜单为「打开主界面 / 退出」。
- 左键单击条目展开缩略详情（完整日期星期、时刻、备注与编辑入口）；底部「新增条目」直达主界面新建表单。

**菜单栏显示策略**（规划）：默认仅黑色缩略图标；设置中可切换「最近条目数字 / 指定条目数值」。数字只显示核心值，完整信息在快捷面板中呈现。

**快捷操作**：当前支持查看、快速新增、置顶（编辑/列表右键）、打开主界面；「完成提醒 / 稍后提醒 / 暂停提醒」依赖提醒类型，随 v0.3 规划。删除与复杂规则不进面板，避免误操作。

### 4.5 配置窗口（主界面）

- 条目列表管理页：增、删、改、置顶；拖拽自定义排序与行右键快捷菜单（编辑/置顶/删除）。
- 条目编辑表单：类型（通栏）→ 实时预览卡（大数字）→ 左栏日期时间锚点（快捷日期 chips + 自研月历 + 时刻步进器 + 重复/显示单位）→ 右栏名称、外观（色板与自定义取色、置顶、备注）。
- 日期时间选择器：自研日历面板替换原生控件，支持可选时/分精度；分钟支持键入、滚轮、按住步进三种调节方式。
- 通用设置页：开机自启；已过期条目是否显示。
- 关于页（M5 实装）：版本、开源地址、许可证。

**设置结构规划**（随功能逐步扩展为四组）：

1. **通用**：启动行为、默认打开方式、日期显示、周起始日；
2. **菜单栏**：图标显示模式、展示数量、默认筛选、重点条目；
3. **提醒**：默认提前时间、声音、稍后提醒时长、免打扰行为；
4. **外观与数据**：浅色 / 深色 / 纯黑、强调色、导入导出、归档管理。

设置项使用结果导向的描述，例如"菜单栏显示最近条目的数字"，不使用需要用户猜测的内部术语。

### 4.6 提醒设计（规划 v0.3）

提醒能力服务于三种类型，而不只属于"提醒"类型：

- 倒数日：支持当天、提前若干天或多个关键节点提醒；
- 正数日：支持周年、整百天等里程碑提醒；
- 提醒：支持指定时刻、重复、稍后提醒与完成。

提醒通知必须包含：条目标题、相对时间、确切时间和清晰动作。用户关闭系统通知后，界面应明确说明影响并提供恢复路径，不能静默失效。

### 4.7 首版（MVP，v0.1）范围

**包含：**

1. 托盘图标 + 左键弹出面板 + 右键菜单（打开主界面 / 退出）；
2. 条目模型：日期倒计时 + 正计时，含时刻精度与每天/工作日循环；
3. 配置窗口的条目增删改、置顶与拖拽排序；
4. 本地数据持久化（JSON 文件），重启后数据保留；
5. 中文界面（结构上保留双语切换能力）。

**不包含（明确排除）：**

- 循环重复扩展至每周/每月/每年（v0.2）；
- 到期提醒与系统通知（v0.3）；
- 云同步、账号体系、多设备；
- 数据导入导出（v0.4）；
- 主题切换（首版跟随系统深浅色做基础适配即可）；
- 条目 Emoji 图标（实验项：名称前展示可选 Emoji，是否纳入视实际使用反馈再定）。

### 4.8 后续路线图（暂定，逐版确认后实施）

| 版本 | 内容                                                                                           |
| ---- | ---------------------------------------------------------------------------------------------- |
| v0.2 | 循环重复扩展（每周/每月/每年）；法定节假日与调休识别；条目分组；临近状态与面板进度展示（潮线） |
| v0.3 | 提醒类型与到期通知（提前 N 天、稍后提醒）；纯黑 OLED 主题；智能提示语；开机自启完善            |
| v0.4 | 数据导入导出（JSON 备份恢复）；农历与生日类型；英文界面（启用预留的 i18n 结构）                |
| v1.0 | 双平台安装包经 GitHub Releases 发布；README、使用说明、图标打磨                                |

优先级判断标准：新能力是否让用户更快理解重要时间，还是只是让软件看起来"功能更多"。应谨慎评估的扩展：复杂自然语言输入、大型日历视图、社交分享与公开纪念页、成就体系与重型统计、过多主题皮肤。

# 第三部分：界面与体验设计

## 5. 界面设计

### 5.1 整体要点

- **整体风格**：安静、轻量、清透、克制；条目颜色仅用于左侧色条与天数强调，不做大面积色块。
- **弹出面板**：无边框窗口，圆角与投影，跟随系统深浅色；macOS 上带半透明材质感（vibrancy 可选）。
- **配置窗口**：常规桌面窗口（780×560），左侧"条目管理 / 通用设置 / 关于"三栏导航（带图标），右侧内容区限宽居中。
- **签名元素**：条目色条采用底部圆弧的「岛屿」造型，左导航底部放置「时屿 · Timelet」字标，与产品图标的岛屿意象呼应。

### 5.2 弹出面板结构（目标形态）

```text
┌────────────────────────────────┐
│ 时屿                 ＋   ···  │
│ 8月30日 · 今天                │
├────────────────────────────────┤
│ 此时 · 今天                    │
│ ● 提交材料              18:30 │
│   提醒 · 还有 2 小时           │
│                                │
│ 将至 · 未来 7 天               │
│ ◔ 去旅行                  12天 │
│   倒数日 · 9月11日             │
│                                │
│ 历时 · 持续计数                │
│ ◡ 搬来上海               328天 │
│   正数日 · 2025年10月6日       │
├────────────────────────────────┤
│ 查看全部条目                    │
└────────────────────────────────┘
```

交互原则：

- 默认展示 5–8 个最相关条目，更多内容通过"查看全部"进入主窗口；
- 条目第一行展示标题和核心数值，第二行展示类型与确切日期；
- 点击条目展开缩略详情（已实装），不在面板内直接编辑；
- 悬停提供轻微背景变化；键盘焦点清楚可见；
- 面板尺寸保持稳定，内容更新时不产生明显跳动；
- 今天没有紧急内容时不制造焦虑：「今天没有需要处理的提醒」。

当前已实装分区结构：此时 / 将至 / 历时 / 已过期，条目为双行结构（标题+数值 / 类型+确切日期）并带类型符号。

### 5.3 主窗口结构（目标形态）

```text
┌──────────────────────────────────────────────────────┐
│ 全部条目        列表 | 时线   搜索        ＋ 新建条目  │
├──────────────┬───────────────────────────────────────┤
│ 全部         │  今天                                 │
│ 即将发生     │  [ 提交材料       提醒      18:30 ]  │
│ 正在累积     │                                       │
│ 提醒         │  接下来 7 天                          │
│              │  [ 去旅行         倒数日      12天 ]  │
│ 岛群 · 分组  │  [ 朋友生日       倒数日      5天  ]  │
│  个人        │                                       │
│  工作        │  更晚                                 │
│              │  [ 搬来上海       正数日     328天 ]  │
│ 归档         │                                       │
│ 设置         │                                       │
└──────────────┴───────────────────────────────────────┘
```

布局原则：

- 轻量侧栏加单一主列表，不默认显示复杂三栏结构；
- 默认使用分组列表而非大卡片网格，以提升扫描速度并控制视觉重量；
- 选中条目后可在原位置展开摘要；需要完整编辑时再进入编辑面板（当前已实装缩略详情与编辑表单分离）；
- 顶部始终只保留一个主要动作："新建条目"。

当前实现为「编辑态表单 / 分组列表（今天 / 接下来 7 天 / 更晚）」二态切换 + 三项导航，时线视图与搜索随 v0.2 规划。

### 5.4 条目单元

每个条目单元由四层信息构成：

1. **符号与色条**：岛屿弧形色条标识归属（已实装），类型符号规划随提醒类型引入；
2. **标题**：最重要的识别信息；
3. **核心数值**：使用等宽数字，避免数值变化造成布局抖动（已实装 `font-variant-numeric: tabular-nums`）；
4. **确切时间**：作为次级信息，消除相对时间的歧义（已实装）。

条目不使用厚重边框和大面积阴影，以留白和轻分隔线形成层级；悬停、选中或临近状态才形成柔和表面（已实装 hover）。

### 5.5 新建 / 编辑条目

新建/编辑使用紧凑面板而非多步骤向导：

1. 顶部通栏选择类型（已实装）；
2. 输入标题（已实装，自动聚焦）；
3. 选择对应日期或时间（已实装：快捷 chips 随类型切换语义）；
4. 「更多选项」放置低频配置（当前实现：置顶、备注常显于外观区；重复/单位在时间区随时刻开关切换）；
5. 类型切换时字段解释同步变化：日期标签在「目标日期 / 起始日期」间切换（已实装）。

保存按钮使用明确文字「保存」，名称或日期未完成时给出前置提示（已实装）。

### 5.6 首次使用与空状态

首次打开不使用多页教学轮播，只展示产品价值和一个主要动作：

> 把重要的日子，安静地放在菜单栏。
> 创建第一个条目

空状态文案（当前已实装引导按钮，文案随版本对齐下述规范）：

- 无条目："这里还没有重要日期。" / "新建第一个条目"
- 筛选无结果："没有符合当前条件的条目。" / "清除筛选"（随筛选功能落地）
- 今日清空："今天没有需要处理的提醒。"（随提醒类型落地）
- 通知未开启："提醒目前无法送达。" / "查看通知设置"（随 v0.3 落地）

空状态可保留一条极简水面曲线或小岛轮廓，但必须同时提供清楚文案和按钮。

### 5.7 意象化界面组件（规划）

除标题命名外，可设计少量专属视觉组件，让"时"和"屿"形成可识别形象：

- **时弧**：不闭合的细圆弧，用于摘要、详情与倒数进度；端点表示当前所在位置。只在重点区域使用，不在每行重复（已实装于编辑表单实时预览卡背景）。
- **屿面**：低矮平缓的曲线表面，用于欢迎页、空状态、重点摘要与窗口底部留白；单色轮廓或极浅色块，不做真实岛屿插画。
- **潮线**：极细的水平进度线，表达"正在接近"（v0.2 面板进度展示）。
- **信标点**：提醒时刻的实心点或短暂扩散圆环；不持续闪烁，不作普通条目装饰（随 v0.3）。
- **时间群岛概览（时线视图）**：水平/纵向时间线上分布岛形节点，未来在一侧、已发生在一侧，今天是基准点；不取代默认列表。

共同约束：**一个界面只突出一种主意象**，避免堆叠成完整海景。

## 6. 设计语言

### 6.1 视觉关键词

**清透、克制、柔和、轻盈、稳定、略带温度。**

以现代系统工具的秩序感为基础，以"时间弧线"和"低矮岛形"建立品牌识别。视觉不能像游戏、旅游或冥想应用，也不能显得像重型效率软件。

> 说明：本节色彩系统已落地为 `src/style.css` 中的设计 tokens（`--ts-*` 变量，含深浅色两组），所有界面一律引用变量，不再散写色值；小字号文本/链接使用深阶时屿蓝 `--ts-primary-text` 保证对比度。

### 6.2 图形语言

- **开放圆弧**：代表尚未闭合、仍在流动的时间；用于进度、类型符号和品牌图形；
- **低矮曲线**：来自岛屿地平线；用于空状态、选中轮廓或页面分区，不作大面积插画；
- **点与刻度**：代表具体时刻；提醒使用单点或短暂涟漪，不持续闪烁；
- **负空间**：水面的主要表达方式；界面通过留白获得轻盈感；
- **柔和圆角**：体现岛屿边界与友好感，但不把所有内容都做成独立胶囊。

### 6.3 类型符号（规划，随提醒类型引入）

三种类型使用同一几何母体，区别来自时间方向：

- **倒数日**：开放圆弧向目标点收束；
- **正数日**：圆弧从起点向外展开；
- **提醒**：时间弧上的一个强调点与短刻度。

符号必须同时配有文字或可读标签，不依赖颜色单独传达类型。

### 6.4 色彩系统

**浅色模式**

| 时屿蓝   | `#2A9CDB` | 品牌主色、主要动作 |
| 潮汐青   | `#2EC7C9` | 进度、轻强调       |
| 深海文字 | `#17232D` | 主文字             |
| 雾灰文字 | `#667783` | 次级文字           |
| 水线分隔 | `#DCE6EB` | 分隔线与边界       |
| 临近琥珀 | `#C98220` | 临近状态           |
| 到期珊瑚 | `#C94F55` | 已到期与危险操作   |
| 累积岛绿 | `#368E76` | 正数日辅助色       |

### 6.5 字体与数字

- 使用系统无衬线字体，让工具自然融入桌面环境（已实装）；
- 标题以中等字重建立层级，不采用巨大字号或强烈品牌字体；
- 倒数与正数的核心数字使用等宽数字，保证数值变化时位置稳定（已实装）；
- 文本层级保持在少量固定等级：窗口标题、分区标题、正文、辅助信息、数字强调；
- 日期格式保持一致；相对时间旁在适当位置提供确切日期。

### 6.6 间距、圆角与层次

- 采用 4 / 8 为基础的间距节奏；相关信息靠近，不相关分区用更大留白隔开；
- 小型控件与菜单使用较小圆角，面板与空状态使用中等圆角；
- 阴影只用于浮层与快捷面板，列表主要依靠背景差和分隔线；
- 所有可点击区域保持宽松，即使图标本身很小也扩大实际操作范围。

### 6.7 图标与插图

- 沿用同一套线性图标风格、相同端点和笔画粗细（导航图标已实装）；
- 菜单栏使用纯黑 / 纯白模板缩略图，跟随系统状态变化（已实装）；
- 正式 App 图标保留清透海蓝与"时弧环岛"的主体结构（已实装）；
- 插图只出现在首次使用、空状态和关于页，保持单线或双色，不进入高频列表。

现有图标资产：`scripts/icons/`（母版、导出尺寸与设计约束见其 README）。

## 7. 动效与反馈

### 7.1 动效原则

动效表达"时间正在靠近"与"内容从水面浮现"，但不制造持续运动：

- 面板打开：轻微淡入与短距离上移，快速完成；
- 新建成功：新条目从列表位置柔和浮现，而不是整页庆祝；
- 完成提醒：条目轻微收束并淡出，提供可撤销提示；
- 临近时刻：状态点可进行一次短暂扩散，不持续呼吸或闪烁；
- 切换筛选：内容交叉淡化，保持空间位置连续；
- 所有动效可被操作打断，并尊重系统"减少动态效果"设置。

动效以短促为主，约 150–250 毫秒；退出比进入更快。倒数数字不逐秒跳动，除非条目明确需要精确到秒（当前时刻条目为分钟级刷新）。

### 7.2 操作反馈

- 点击、悬停、键盘焦点和禁用状态都有可见差异（已实装）；
- 创建、修改、完成和删除后给出明确反馈；
- 删除提供确认或短时撤销，避免不可逆误操作（已实装删除确认弹窗）；
- 加载时间稍长时显示轻量占位，不让界面像失去响应；
- 错误信息说明"发生了什么"以及"如何恢复"（已实装：保存前置提示、自启失败提示）。

## 8. 文案语言

### 8.1 基本语气

简洁、平静、具体。先说事实，再提供动作。避免命令式催促、焦虑化词汇和过多感叹号。

### 8.2 时间表达示例

- 推荐："距春节还有 18 天"、"搬来上海已经 328 天"、"喝药 · 今天 18:30 · 还有 2 小时"；
- 不推荐：只显示 `D-18`、`+328` 而没有上下文；
- 不推荐："警告！任务即将过期！"

### 8.3 品牌文案的使用边界

可以在欢迎页或关于页使用：

> 每一个重要时刻，都是时间里的一座小岛。

内容标题可使用"此时、时线、岛群"等品牌化名称；按钮、状态和操作坚持普通语言，如"条目、提醒、分组、归档"，不用隐喻代替关键动作。

## 9. 易用性与无障碍

- 菜单栏面板和主窗口支持完整键盘导航，并提供清晰焦点状态（部分实装：Esc 路径、自动聚焦；完整 Tab 导航待验证）；
- 图标按钮具有文字提示或可读名称，不依赖用户猜测；
- 类型与状态不只用颜色区分，同时使用符号和文字；
- 主文字满足对比要求，浅色与深色模式分别校验；
- 支持系统文字缩放；标题过长时优先合理换行或显示完整提示；
- 动效遵循系统"减少动态效果"偏好；
- 通知、稍后提醒与删除等关键操作都有可恢复路径；
- 高频点击区域保持舒适尺寸，避免要求精确点击小图标；
- 屏幕阅读顺序与视觉顺序一致；核心数值读作完整语义，例如"还有十八天"。

# 第四部分：工程与推进

## 10. 技术架构

```
┌────────────────────────────────────────────┐
│ 前端（Vue 3 + TS）                          │
│  ├─ 面板视图（弹出面板，小窗口）              │
│  ├─ 配置视图（配置窗口）                     │
│  └─ i18n（zh-CN 首版，预留 en-US）           │
├────────────────────────────────────────────┤
│ Tauri 桥接层（invoke / event）              │
│  ├─ entry_list / entry_save / entry_delete │
│  ├─ entry_reorder / settings_get / set     │
│  └─ 面板菜单 / 主界面直达动作               │
├────────────────────────────────────────────┤
│ Rust 侧（src-tauri）                       │
│  ├─ 托盘图标与菜单（双平台行为差异封装）      │
│  ├─ 窗口管理（弹出定位、失焦收起、状态记忆）  │
│  └─ 存储模块（JSON 文件读写，原子写入）       │
└────────────────────────────────────────────┘
```

关键决策：

1. **存储**：本地 JSON 文件，位于系统标准应用数据目录（macOS `~/Library/Application Support/`，Windows `%APPDATA%`），写入采用"写临时文件 + 原子替换"避免损坏；条目与设置、窗口状态分文件存储。
2. **窗口定位**：弹出面板显示前，通过托盘图标在屏幕上的坐标计算窗口位置（macOS 在图标下方、Windows 在任务栏上方），差异封装在 Rust 侧统一函数内。
3. **收起行为**：监听窗口失焦事件自动隐藏面板，两个平台行为一致。
4. **数据倒计时计算**：前端按本地时区计算，纯日期条目按自然日（非 24 小时制），带时刻条目按分钟精度并对齐"下一次发生"（循环条目）。

## 12. 风险与注意事项

- **Windows 弹窗定位**：任务栏可能在屏幕四边，托盘图标坐标获取方式与 macOS 不同，M1 中预留手动测试项。
- **macOS 签名**：未签名应用首次打开需右键放行；正式分发是否申请 Apple Developer 签名，在 M5 前另行确认。
- **自然日计算**：跨时区/夏令时场景以"本地日历日"为准，避免出现"差一天"的观感问题。
- **数据格式演进**：0.x 阶段 JSON 结构可能调整，存储模块保留版本字段（`schemaVersion`）以便后续迁移。
- **设计语言迁移**：第 6 节色彩 tokens 与当前实现存在色值差异，迁移需整体校验深浅色对比度，避免逐个控件零散替换。

## 13. 设计验收清单

每次界面相关合并前，除工程验收标准外，对照以下清单自查：

### 信息与功能

- [ ] 菜单栏打开后，最重要的条目无需滚动即可看到。
- [ ] 各类型既能快速区分，也共享一致的操作逻辑。
- [ ] 普通条目只填写三个核心信息即可创建。
- [ ] 相对时间与确切日期不会互相矛盾或产生歧义。
- [ ] 设置与高级字段不会干扰高频使用。

### 视觉与品牌

- [ ] "时"通过方向、进度、刻度表达，而不是重复使用钟表图案。
- [ ] "屿"通过边界、聚合、曲线与留白表达，而不是场景化插画。
- [ ] 界面在缩小、深色模式和大量条目下仍保持轻盈。
- [ ] 状态颜色具有文字或符号辅助，不单独依赖颜色。
- [ ] 正式图标、菜单栏缩略图与界面图标属于同一几何语言。

### 交互与无障碍

- [ ] 主要功能可通过键盘完成，焦点顺序自然。
- [ ] 点击、悬停、选中、禁用和错误状态均清楚可辨。
- [ ] 动效短促、有意义，并支持减少动态效果。
- [ ] 空状态提供清楚下一步，不出现空白页面。
- [ ] 删除、提醒失败和权限关闭都有明确恢复路径。

## 14. 最终设计命题

**时屿不是把时间做成海岛主题，而是把重要时间理解为一座座值得被看见、被靠近、被记住的小岛。**

产品在日常中应像平静水面一样退后；当某个时刻靠近，它才以清楚、温和、准确的方式浮现。这一原则应同时约束功能数量、信息层级、视觉重量、提醒频率和动效强度。

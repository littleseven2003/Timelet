# 第一部分：产品定义

## 1. 产品定位

**Timelet（时屿）** 是一款常驻系统托盘的倒计时工具：在 macOS 菜单栏 / Windows 任务栏显示一个小图标，点击后在图标旁弹出一个小面板，展示用户自定义的各类倒计时与正计时条目；通过快捷面板的“打开主窗口”或托盘菜单进入管理界面，对条目进行增删改。提醒类型仍待实现。

- **一句话定位**：把重要的日子安静地放在菜单栏，让用户随时知道"还有多久""已经多久""何时该做"。
- **名称释义**："时"指时间，"屿"指时间之海中的一座座小岛——每个倒计时条目都是时间线上被标记的一座岛屿。
- **产品类型**：轻量化倒数日 / 正数日 / 提醒工具，以菜单栏为主要日常入口，以主窗口为管理入口。

时屿不是一个完整日历，也不是任务管理器。它只承担一件事：把少量真正重要的时间节点，以最轻的方式留在用户视线附近。

### 产品气质

- **轻**：不打断工作，不要求频繁维护，不把简单需求复杂化。
- **静**：视觉克制、提醒适度，平时退居背景，需要时立即可见。
- **清**：时间状态一眼可读，类型、日期和下一步操作都明确。
- **准**：相对时间与确切日期同时可信，提醒状态始终可确认。
- **暖**：重要日期往往承载关系、记忆与期待，文案应有人情味，但不过度抒情。

### 设计目标

1. 用户点击菜单栏图标后，约 3 秒内找到最关心的条目和剩余时间。
2. 新建普通条目时，只填写标题、类型、日期三个核心信息即可完成。
3. 倒数日、正数日与提醒在视觉上容易区分，但仍属于同一套设计系统。
4. "时"与"屿"的意象进入信息结构、图形和动效，而不是成为表面装饰。
5. 即使用户完全不了解品牌意象，也能自然理解并高效使用。

### 明确边界

时屿不以复杂日程排布、项目协作、社交分享、重型统计或持续打卡为核心。它不与系统日历争夺"全部时间"，而是管理用户主动挑选出来的"重要时间"。

## 2. 核心意象与产品隐喻

### 2.1 "时"：方向、距离与节律

"时"不只是一枚钟表，更重要的是时间相对于某个节点的关系：

- 倒数日是**向节点靠近**；
- 正数日是**从节点向外延伸**；
- 提醒是**在时间线上被点亮的瞬间**（规划，见 4.6）；
- 周期提醒是**反复抵达的节律**。

因此，界面中的时间表达应优先使用"方向、距离、进度和刻度"，而不是到处放置钟表图案。

### 2.2 "屿"：独立、承载与聚合

每一个条目都像一座小岛：边界清楚、彼此独立，并承载一件重要的事。多个条目共同构成用户自己的"时间群岛"。

| 意象        | 产品含义       | 设计表达                           |
| ----------- | -------------- | ---------------------------------- |
| 一座岛      | 一个时间条目   | 独立但轻薄的条目单元               |
| 岛的轮廓    | 条目的边界     | 柔和圆角、清楚分组、不过度描边     |
| 岛群        | 多个相关条目   | 可用"岛群 · 分组"作标题（规划）    |
| 水面        | 安静的背景环境 | 大量留白、低对比背景、清透层级     |
| 潮汐        | 时间逐渐靠近   | 进度、状态变化与克制动效           |
| 灯塔 / 信标 | 需要注意的时刻 | 提醒点、状态标记、通知反馈（规划） |

### 2.3 融合原则：语义优先，装饰退后

- 不把主界面画成海岛地图，不使用写实海浪、沙滩、椰树等插画；允许在整页底层使用低对比海雾、远屿轮廓与潮线，规则见 6.8。
- 不用晦涩的诗意词替代常用功能名称。界面写"新建条目""分组""归档"，而不是强迫用户理解"造岛""岛群""沉岛"。
- 品牌语言主要通过开放圆弧、低矮曲线、留白、清透颜色和微小的"浮现"动效体现。
- 品牌化词汇可用于视图、分区标题、欢迎页与空状态；核心操作始终直接明确。

### 2.4 品牌化命名的使用层级

"时""屿"相关词汇可以直接成为视图、分区或内容标题，采用"**意象标题 + 清晰上下文**"的方式：标题负责气质，条目内容或辅助说明负责解释。

| 品牌化标题          | 已确认含义与位置                                                          | 实现状态                        |
| ------------------- | ------------------------------------------------------------------------- | ------------------------------- |
| **此时**            | 主窗口默认活动条目视图；列表中的“此时 · 今天”分区承载今天条目与待处理提醒 | M3 已有日期分区，完整视图待对齐 |
| **将至**            | 从明日起未来 7 个本地日历日，不包含今天                                   | 日历边界已通过针对性回归        |

## 3. 目标平台与产品结构

### 3.1 平台形态

- **macOS 12+**：菜单栏图标；左键点击在图标正下方弹出面板（popover 式），右键显示托盘菜单。
- **Windows 10/11**：任务栏托盘图标；左键点击在任务栏图标上方弹出面板，右键显示托盘菜单。
- 应用无常驻主窗口，仅"弹出面板"与"配置窗口"两类窗口。
- 支持开机自启（设置为可选项，默认关闭；M3 已实装）。

### 3.2 使用层级

```text
菜单栏缩略图
    ↓ 点击
快捷面板：查看当前条目、快速操作、快速新增
    ↓ 需要集中管理时
主窗口：全部条目、筛选搜索、新建编辑、归档、设置与关于
```

- **菜单栏是"近岸"**：承载高频、短时、无需思考的操作——看一眼、快速新增、打开主界面。内容有限但始终可达。
- **主窗口是"群岛全景"**：集中管理全部条目、理解时间分布和修改配置。可以展示更多上下文，但保持单一主任务，不演变成复杂仪表盘。
- **设置是"水面之下"**：低频内容，独立于日常列表，不应让配置项长期占据主界面。

# 第二部分：功能设计

## 4. 功能大纲

### 4.1 核心概念：条目（Entry）

所有展示内容以"条目"为基本单位，用户只需理解一种对象，再通过类型决定它如何显示和提醒。

#### 类型

| 类型   | 用户问题   | 目标主显示形式 | 典型场景               | 状态                   |
| ------ | ---------- | -------------- | ---------------------- | ---------------------- |
| 倒数日 | 还有多久？ | `还有 18 天`   | 节日、旅行、考试、生日 | 类型已实装，文案待对齐 |
| 正数日 | 已经多久？ | `已经 328 天`  | 纪念日、习惯起点、入职 | 类型已实装，文案待对齐 |
| 提醒   | 何时该做？ | `今天 18:30`   | 喝药、缴费、预约、周期 | 规划 v0.3              |

#### 当前存储字段

以下为数据结构版本 2 的现有模型；提醒、完成、分组等新增字段须在实现时明确版本策略，交互定稿中的示例对象不作为存储协议。

| 字段                  | 类型                     | 说明                                                                             |
| --------------------- | ------------------------ | -------------------------------------------------------------------------------- |
| id                    | string                   | 唯一标识（UUID）                                                                 |
| name                  | string                   | 条目名称，如"项目上线"、"已坚持晨跑"                                             |
| type                  | `countdown` \| `elapsed` | 倒计时（距目标日）/ 正计时（自起始日已过）                                       |
| date                  | string (ISO 日期)        | 目标日期（倒计时）或起始日期（正计时）                                           |
| time                  | string? (HH:mm)          | 可选时刻；带时刻条目按小时/分钟精度计算展示                                      |
| repeat                | string?                  | 发生频率；缺失为仅一次，daily 为每天，workday 为周一至周五，仅带时刻的倒数日生效 |
| displayUnit           | string?                  | 展示单位（天/周/月/年），缺失按天                                                |
| note                  | string?                  | 选填备注，面板悬停与缩略详情中展示                                               |
| pinned                | boolean                  | 是否置顶显示                                                                     |
| sortIndex             | number?                  | 手动排序值（拖拽后生成）                                                         |
| createdAt / updatedAt | string                   | 创建/更新时间                                                                    |

已确认字段层级：类型 → 标题 → 日期/时间 → 发生频率 → 语义预览。发生频率仅在“倒数日 + 包含时刻”时出现，直接提供“仅一次 / 每天 / 周一至周五”；备注、分组、置顶、显示单位及适用的阶段规则进入“更多选项”。条目不提供单独颜色设置，类型与状态颜色由统一设计变量决定；普通日期型倒数日与正数日仍只需类型、标题和日期三个核心信息。

### 4.2 条目状态

以下为已确认目标语义，不能把现有过期过滤或日期边界问题视为已修复：

- **平常 / 临近**：临近默认取明日起 7 个日历日；今天单列，未来 7 天示例不得混入 12 天条目。
- **今天**：纯日期型条目显示“就是今天”，当天结束前不因午夜已过而隐藏；时刻型同时显示准确时刻。
- **已过去**：过去的倒数日显示“已过去 N 天”，可查看或归档，不用提醒的逾期警告文案。
- **持续计数**：正数日显示“已经 N 天”，没有过期状态；未来起始日显示“尚未开始 · 还有 N 天”，不出现负数“已经”。
- **已过期 / 待处理**：仅用于到点后尚未处理的提醒，提供完成、稍后提醒等动作（提醒能力规划）。
- **已完成 / 已归档**：离开默认活动视图；完成用于提醒发生记录，归档保留条目，可恢复。重复提醒的完成只作用于本次发生。

时间状态由当前本地日期/时刻计算，与完成、归档等生命周期分开。循环条目的相对数值、确切日期、分区和排序使用同一个有效发生时间；下一次发生不得早于起始日期。

带时刻倒数日的发生频率规则：仅一次到点后保持过期；每天到点后推进至下一日同一时刻；周一至周五跳过周六、周日。日期表示首次生效日。例如“下班”设置为每天 17:00，当天 17:00 前显示距离本次下班的小时与分钟，之后立即显示距离次日 17:00 的时间。

### 4.3 排序与组织

当前实现：置顶优先；未过期倒计时按截止时间升序；正计时按起始日期升序；已过期倒计时置底；用户手动拖拽后按手动顺序（置顶仍优先）。

已确认目标排序：今天与待处理提醒 → 置顶条目 → 即将发生的倒数日 → 正数日与较远条目；已完成和归档独立浏览，不混入活动列表。摘要中的条目不在列表重复。手动排序作为独立模式保留，不通过跨时间分区拖动暗中改变日期或置顶状态。

用户可按类型、分组、日期或置顶状态筛选（规划 v0.2）；搜索覆盖标题、备注和分组（规划）。分组属于可选能力，不在初次使用时强制出现。

### 4.4 快捷面板

- 高频入口，用于查看重点、展开条目与快速操作；默认选取 6 个最相关条目，设置范围 5–8 条，替代旧版全部条目滚动列表。
- 顶部为“时屿”、当天日期与星期、快速新增；暂停提醒在提醒能力可用后显示。
- 约 320–334px 宽，按内容适配高度并限制在屏幕可用范围内；超出范围允许滚动，但优先把待处理内容放在首屏。
- 底部只保留 **“打开主窗口”**：窗口轮廓图标、文字与向右箭头。进入完整条目列表，不进入新建表单、设置或主题切换。
- 点击外部收起；条目单击展开完整日期、备注及操作。删除和复杂规则只在主窗口处理。
- 托盘右键菜单保留打开主窗口与退出；面板右键可保留编辑、打开主窗口等快捷动作，但不能替代可见的底部入口。

菜单栏默认仅图标。“最近条目 / 指定条目数字”为后续能力，须在实现前确认平台差异与回退方式；草案中的菜单栏数字仅为示例，不代表两端已支持。

### 4.5 主窗口

- 轻侧栏 + 单一内容区；默认“此时”查看活动条目，按“倒数日 / 正数日 / 提醒”筛选。可选分组位于中部，已完成、归档、设置与关于时屿位于底部。
- 提供搜索、列表/时线切换、近屿重点摘要、条目展开与管理操作；设置和关于使用独立内容页，不叠加在列表上。
- 新建与编辑改为单列紧凑表单，折叠更多选项；保留现有日历、时刻步进、备注、色板等有效能力，不继续使用“左侧日期 / 右侧名称外观”的双栏结构。
- 设置与关于内容分离；“关于时屿”作为本次界面定稿的一部分，不再把入口统一推迟到发布阶段。发布阶段补齐真实版本、开源地址和许可证，不展示虚构信息。

设置按能力逐步扩展为通用、菜单栏、提醒、外观与数据四组。已确认外观为跟随系统 / 浅色 / 深色；纯黑主题仍为后续候选。未实现能力不放不可用的空开关。

### 4.6 提醒设计（规划 v0.3）

提醒能力服务于三种类型，而不只属于"提醒"类型：

- 倒数日：支持当天、提前若干天或多个关键节点提醒；
- 正数日：支持周年、整百天等里程碑提醒；
- 提醒：支持指定时刻、重复、稍后提醒与完成。

提醒通知必须包含：条目标题、相对时间、确切时间和清晰动作。用户关闭系统通知后，界面应明确说明影响并提供恢复路径，不能静默失效。

### 4.7 首版（MVP，v0.1）范围

**包含：**

1. 托盘图标 + 左键弹出面板 + 右键菜单（打开主界面 / 退出）；
2. 条目模型：日期倒计时 + 正计时，含时刻精度与每天/工作日循环；
3. 配置窗口的条目增删改、置顶与拖拽排序；
4. 本地数据持久化（JSON 文件），重启后数据保留；
5. 中文界面（结构上保留双语切换能力）。

**不包含（明确排除）：**

- 循环重复扩展至每周/每月/每年（v0.2）；
- 到期提醒与系统通知（v0.3）；
- 云同步、账号体系、多设备；
- 数据导入导出（v0.4）；
- 主题切换（首版跟随系统深浅色做基础适配即可）；
- 用 Emoji 替代类型或操作图标；类型图标固定采用第 6.3 节的线性体系。

# 第三部分：界面与体验设计

## 5. 界面设计

### 5.1 整体要点（已确认设计）

- 海雾与夜海两套外观；克制的表面、留白与线条。全页底层允许远屿和潮线，重点条目采用轻微不对称屿面，其余列表保持安静。
- 主窗口默认 780×560、最小 700×520；侧栏约 146px，必要时可收起；内容区根据可用高度滚动，不通过强行缩小字体塞入全部内容。
- 正式应用与托盘图标复用现有资产。产品标识位于侧栏顶部，侧栏底部不再放字标或常驻标语。
- 默认主任务是浏览条目。只有列表/管理界面保留一个“新建条目”主动作；关于页隐藏新建与列表工具。
- 交互定稿采用展开式展示以便审阅；它的整体高度不等同于桌面窗口规格，正式实现须验证最小窗口、缩放和滚动。

### 5.2 快捷面板

```text

8月31日 · 星期一

此时 · 今天
  提交材料                         18:30
  提醒 · 8月31日 · 工作              今天

近屿 · 置顶
  去看一场海
  9月5日                             5天
  ────────────●──  潮线

将至 · 未来7天 / 历时 · 持续计数 / 更远
  [类型图标] 标题
             每天 · 17:00             5时3分

[窗口图标] 打开主窗口                    ›
```

- 置顶摘要紧凑展示一个适合的倒数日，潮线由真实区间计算。待处理提醒优先；其余条目按相同分区规则补足展示名额，不重复置顶条目。
- 展开提醒后提供完成、稍后提醒、编辑、置顶；其他条目提供编辑、置顶。未实现提醒前不展示相关操作。
- “打开主窗口”是唯一底部入口；图标使用带顶栏和侧栏分隔的窗口轮廓，不使用太阳、设置符号或单独的外链箭头。
- 打开完整列表时清除列表筛选和搜索，但不得丢弃尚未保存的编辑内容；必要时保留草稿或提示后再切换。
- 设置和关于保留在主窗口，不在面板底部与打开窗口并排混用。
- 快捷面板采用克制的两行信息层级：类型图标跨两行，标题独占首行；第二行左侧显示短日期或“每天 / 周一至周五 · 时刻”，右侧显示短时间值。标题、次要信息和核心时间各自保持单行，不增加卡片、徽标或额外交互。
- 面板中的核心时间省略“还有”等可由类型图标、分区和状态色共同表达的前缀，使用“5天、5时3分、已31天、超2天”等短格式；主窗口继续使用完整自然语言。空间仍不足时仅省略标题或次要信息，并通过悬停提示与可读名称保留完整语义，不产生横向滚动。

### 5.3 主窗口

```text
时屿 Timelet    │ 此时                         ＋新建条目
                │ 8月31日 · 星期一
此时            │
倒数日          │ 近屿 · 置顶条目

  个人 / 工作   │ 此时 · 今天       提交材料    18:30

归档            │ 更远 · 7天以后    妈妈的生日    18天

```

- “此时”导航代表全部活动条目；同名分区以“此时 · 今天”明确当天语义。常用导航按类型命名，不再使用“条目管理 / 通用设置 / 关于”的旧三项结构。
- 默认使用列表而非卡片网格。列表行按内容分区，行间使用轻分隔；标题与核心数字第一行，类型与确切日期第二行。
- **近屿摘要最多一个**，仅在默认、未搜索的列表出现；筛选、时线、归档、设置、关于中隐藏。摘要中的条目从下方列表排除，无适合置顶条目时不占空位。
- 摘要左侧为标题、确切日期与起点说明，右侧为开放时弧及核心天数。真正到期的待处理提醒优先于摘要。
- 页脚仅显示条目数量；不再常驻“仅本地 · 安静相伴”。侧栏不再常驻“每一个重要时刻……”等产品介绍。
- 分组为空时隐藏该区；搜索覆盖标题、备注和分组，空结果提供清除筛选入口。

### 5.4 条目单元与操作

1. **类型图标**：采用 6.3 的统一路径与颜色，配文字标签；不以旧版色条或 Emoji 代替类型。
2. **标题**：第一识别信息；主窗口长标题合理换行，快捷面板保持单行并在空间不足时省略，不遮挡核心时间与操作。
3. **核心时间**：主窗口使用倒数日“还有 N 天”、正数日“已经 N 天”、提醒“今天 18:30”等完整语义；快捷面板使用“N天、N时N分、已N天、超N天”等短格式。数字采用等宽形式，避免跳动。
4. **确切日期**：与相对时间使用同一计算结果；循环条目展示有效发生日期。

点击条目展开备注与动作，编辑打开完整表单。主窗口支持复制、归档与恢复；提醒支持完成与稍后提醒，动作与类型、生命周期匹配。归档、完成等操作提供撤销；删除放入更多操作并确认，不常驻整列危险按钮。手动排序与按时间自动分区明确分开。

### 5.5 新建 / 编辑条目

采用单列紧凑表单，不做多步骤向导，不让大数字预览先于核心输入：

1. 顶部选择倒数日 / 正数日 / 提醒，使用统一类型图标。
2. 输入标题，打开表单时聚焦标题。
3. 选择日期与必要的时刻；复用已有日期控件、快捷日期与时刻步进能力。示例中的原生日期输入不要求替换现有日历组件。
4. 带时刻的倒数日紧接日期显示“发生频率”，明确选择仅一次、每天或周一至周五；选择重复后，日期标签改为“首次日期”。
5. 显示一块紧凑语义预览：类型、标题、相对时间和确切日期；重复条目同时显示频率和“下次”发生时间，承载在轻屿面上。
6. 提醒开关：普通倒数日与正数日默认关闭，提醒类型默认启用；需要时再解释权限。
7. “更多选项”折叠备注、分组、置顶、显示单位及适用的阶段/里程碑规则。未实现字段不展示空控件。
8. 底部“取消 / 创建条目”，编辑时改为“取消 / 保存修改”。不继续使用含糊的统一“保存”。

切换类型时同步更新“目标日期 / 起始日期 / 提醒日期”的标签、解释、预览与有效字段。普通条目仅三个核心字段即可创建；提醒必须有有效时刻。输入缺失时就地提示，不显示 NaN 或伪造时间。保存失败保留输入，防止重复提交；退出未保存编辑需保护草稿。

### 5.6 首次使用与空状态

首次使用直接说明“还没有条目”并提供“新建第一个条目”，不重复品牌标语或展示多页轮播。

- 无条目：“这里还没有重要日期。” / “新建第一个条目”。
- 筛选无结果：“没有符合当前条件的条目。” / “清除筛选”。
- 无已完成提醒：“还没有已完成的提醒。”。
- 归档为空：“这里还没有归档条目。”；可有简短远屿说明，但功能名称仍为归档。
- 通知未开启：“提醒目前无法送达。” / “查看通知设置”。

区分首次无数据、筛选隐藏、加载失败与数据损坏；错误不能回退成空列表。小岛轮廓只作辅助，不代替清楚文案与恢复动作。

### 5.7 时弧、屿面与潮线

- **时弧**：重点摘要采用约 270° 开放圆弧，起点为记录日期，终点为目标日期，端点表示当前进度；只在重点区域强调，不在每行重复大圆环。
- **进度规则**：`进度 = clamp((当前日期 − 起点日期) / (目标日期 − 起点日期), 0, 1)`，纯日期按本地日历日差计算。区间无效、无可信起点或终点不晚于起点时不画进度，只展示真实时间；循环条目须另有清楚的本次区间。
- **屿面**：重点摘要为低重心、轻微不对称的底部轮廓，浅色曲面承载文字；保持文字可读，不作写实风景。
- **潮线**：面板用细水平线替代完整时弧，与主窗口共享进度来源，不使用固定百分比。
- **信标**：提醒图标与今天状态用静止的强调点、文字和确切时刻，不持续闪烁。

一个界面只突出一处重点意象；整页背景的远屿与潮线保持更低对比度，不与功能进度争夺注意力。

### 5.8 时线视图

时线与列表共享筛选和条目数据，作为可选浏览方式，不取代默认列表。按有效日期顺序排列，今天为基准，节点采用轻岛形；过去的持续计数内容单列。切换时隐藏近屿摘要，避免同一条目重复。

当前定稿采用等距节点，必须保留“按日期排列，节点间距不代表时长”的说明；不得让布局看起来像按比例时间轴。若以后使用比例时间轴，须采用真实时间尺度与刻度。

### 5.9 设置与关于时屿

设置按 4.5 的四组逐步接入，跟随系统 / 浅色 / 深色选择需同步主窗口与面板；暂无实现的能力不展示空开关。

主窗口侧栏底部设置独立 **“关于时屿”**，使用信息图标，内容包括：

- 正式应用标识、时屿 / Timelet、倒数日 · 正数日 · 提醒的产品定位。
- 产品介绍：“把重要的日子，安静地放在菜单栏。”
- 设计理念：“每一个重要时刻，都值得被记住。”以及时弧、岛屿的简短含义。
- 本地与隐私：条目与设置保存在本机，无需登录账号；实现变化时同步修订说明。
- 真实版本、开源地址与许可证在发布准备时补全；不伪造版本或提供无效链接。

关于页隐藏新建按钮、搜索、列表/时线切换和条目数量；返回列表后恢复。设置页不再重复产品介绍，主列表和面板中不常驻上述文案。

## 6. 设计语言

### 6.1 视觉关键词

**清透、克制、柔和、轻盈、稳定、略带温度。**

以现代系统工具的秩序感为基础，以"时间弧线"和"低矮岛形"建立品牌识别。视觉不能像游戏、旅游或冥想应用，也不能显得像重型效率软件。

> 现有 `src/style.css` 已有 `--ts-*` 变量体系；本节是本次定稿的目标值，尚未全部同步到软件。实现时复用语义变量统一迁移，所有界面引用变量，小字号文本与按钮使用满足对比度的深/浅阶。

### 6.2 图形语言

- **开放圆弧**：代表尚未闭合、仍在流动的时间；用于进度、类型符号和品牌图形；
- **低矮曲线**：来自岛屿地平线；用于空状态、选中轮廓或页面分区，不作大面积插画；
- **点与刻度**：代表具体时刻；提醒使用单点或短暂涟漪，不持续闪烁；
- **负空间**：水面的主要表达方式；界面通过留白获得轻盈感；
- **柔和圆角**：体现岛屿边界与友好感，但不把所有内容都做成独立胶囊。

### 6.3 类型与功能图标（已确认）

类型图标统一使用 24×24 绘制网格、1.75px 笔画、圆角端点与连接；普通列表约 21px、类型选择约 20px、语义预览约 26px。侧栏、面板、列表和表单复用同一组路径，不分别绘制近似图标。

| 类型   | 图形                           | 语义               |
| ------ | ------------------------------ | ------------------ |
| 倒数日 | 带顶部刻度与指针的开放计时环   | 向目标时刻靠近     |
| 正数日 | 带外向箭头的开放时弧与时间指针 | 从起点持续延伸     |
| 提醒   | 铃形轮廓与右上信标点           | 在指定时刻提醒注意 |

这些定稿图形替代旧版仅由零散圆弧和圆点构成的类型符号；必须配文字或可读标签，不单靠颜色区分。精确路径保存在交互参照的 `typePaths` 中。

功能图标采用相同线性语言：打开主窗口为窗口轮廓，设置为调节滑杆，关于为信息符号。图标按钮具备可读名称，不能用太阳代替窗口操作。

### 6.5 字体与数字

- 使用系统无衬线字体，让工具自然融入桌面环境（已实装）；
- 标题以中等字重建立层级，不采用巨大字号或强烈品牌字体；
- 倒数与正数的核心数字使用等宽数字，保证数值变化时位置稳定（已实装）；
- 文本层级保持在少量固定等级：窗口标题、分区标题、正文、辅助信息、数字强调；
- 日期格式保持一致；相对时间旁在适当位置提供确切日期。
- 字重以 400 / 500 为主；窗口标题 21–23px、正文 13–14px、辅助信息通常 12px、普通时间数字 21–23px、近屿核心数字 40–44px。小尺寸日期端点等非关键注释可以更小，但核心信息不得依赖小字，须通过桌面缩放与可读性验证。

### 6.6 间距、圆角与层次

- 采用 4 / 8 为基础的间距节奏；相关信息靠近，不相关分区用更大留白隔开；
- 小型控件通常 6–9px 圆角，主窗口约 16px、快捷面板约 14px；近屿摘要可使用 12 / 12 / 28 / 12px 的轻微不对称轮廓；
- 阴影只用于浮层与快捷面板，列表主要依靠背景差和分隔线；
- 所有可点击区域保持宽松，即使图标本身很小也扩大实际操作范围。

### 6.7 图标与插图

- 沿用同一套线性图标风格、相同端点和笔画粗细（导航图标已实装）；
- 菜单栏使用纯黑 / 纯白模板缩略图，跟随系统状态变化（已实装）；
- 正式 App 图标保留清透海蓝与"时弧环岛"的主体结构（已实装）；
- 具象插图只在空状态和关于页按需使用；高频列表允许第 6.8 节的低对比背景轮廓，不叠加写实海景、贴纸或持续运动。

现有图标资产：`scripts/icons/`（母版、导出尺寸与设计约束见其 README）。

### 6.8 整页背景意象（已确认）

主窗口、快捷面板和编辑表单都不再使用完全平面的纯色底；在不透明应用表面之上、文字和控件之下叠加静态背景：

- **海雾**：从右上与右下边缘自然淡入的宽缓色晕；中部保留阅读留白。
- **远屿**：底部偏右的低矮非对称轮廓，远近两层形成轻微层次。
- **潮线**：沿岛岸走向的少量细线，只作底层意象，不带进度端点，不与功能潮线混淆。

| 背景角色   | 浅色      | 深色      |
| ---------- | --------- | --------- |
| 海雾色晕   | `#E2F0F7` | `#203E50` |
| 地平线底色 | `#EDF6F7` | `#1B333E` |
| 远屿       | `#DCECF0` | `#294854` |
| 近岸       | `#CFE4E9` | `#325563` |

装饰层限于窗口边界，无指针事件、无键盘焦点，辅助阅读忽略；不会改变内容尺寸或造成横向溢出。背景不持续动画，高对比度或强制颜色模式下隐藏。输入、按钮和选中项保持清楚表面；减少动态效果不影响读取信息。

## 7. 动效与反馈

### 7.1 动效原则

动效表达"时间正在靠近"与"内容从水面浮现"，但不制造持续运动：

- 面板打开：轻微淡入与短距离上移，快速完成；
- 新建成功：新条目从列表位置柔和浮现，而不是整页庆祝；
- 完成提醒：条目轻微收束并淡出，提供可撤销提示；
- 临近时刻：状态点可进行一次短暂扩散，不持续呼吸或闪烁；
- 切换筛选：内容交叉淡化，保持空间位置连续；
- 所有动效可被操作打断，并尊重系统"减少动态效果"设置。

动效以短促为主，约 150–250 毫秒；退出比进入更快。倒数数字不逐秒跳动，除非条目明确需要精确到秒（当前时刻条目为分钟级刷新）。

### 7.2 操作反馈

- 点击、悬停、键盘焦点和禁用状态都有可见差异（已实装）；
- 创建、修改、完成和删除后给出明确反馈；
- 删除提供确认或短时撤销，避免不可逆误操作（已实装删除确认弹窗）；
- 加载时间稍长时显示轻量占位，不让界面像失去响应；
- 错误信息说明"发生了什么"以及"如何恢复"（已实装：保存前置提示、自启失败提示）。

## 8. 文案语言

### 8.1 基本语气

简洁、平静、具体。先说事实，再提供动作。避免命令式催促、焦虑化词汇和过多感叹号。

### 8.2 时间表达示例

- 推荐："距春节还有 18 天"、"搬来上海已经 328 天"、"喝药 · 今天 18:30 · 还有 2 小时"；
- 不推荐：只显示 `D-18`、`+328` 而没有上下文；
- 不推荐："警告！任务即将过期！"

### 8.3 品牌文案的使用边界

产品介绍与价值表达集中到主窗口“关于时屿”。“每一个重要时刻，都值得被记住。”及本地数据说明不再常驻侧栏或列表页脚；不保留“仅本地 · 安静相伴”这一装饰性状态文案。列表页脚只呈现真实条目数量。

“此时、将至、历时、近屿、时线、岛群”可用于信息组织，并配清楚上下文。按钮与操作使用“新建条目、打开主窗口、完成、稍后提醒、归档、删除、设置、关于时屿”。首次使用与空状态先解释当前状态和下一步，不再复述产品标语。

## 9. 易用性与无障碍

- 菜单栏面板和主窗口支持完整键盘导航，并提供清晰焦点状态（部分实装：Esc 路径、自动聚焦；完整 Tab 导航待验证）；
- 图标按钮具有文字提示或可读名称，不依赖用户猜测；
- 类型与状态不只用颜色区分，同时使用符号和文字；
- 主文字满足对比要求，浅色与深色模式分别校验；
- 支持系统文字缩放；主窗口标题过长时合理换行，快捷面板省略时提供完整提示；
- 动效遵循系统"减少动态效果"偏好；
- 通知、稍后提醒与删除等关键操作都有可恢复路径；
- 高频点击区域保持舒适尺寸，避免要求精确点击小图标；
- 屏幕阅读顺序与视觉顺序一致；核心数值读作完整语义，例如"还有十八天"。

# 第四部分：工程与推进

## 10. 技术架构

```
┌────────────────────────────────────────────┐
│ 前端（Vue 3 + TS）                          │
│  ├─ 面板视图（弹出面板，小窗口）              │
│  ├─ 配置视图（配置窗口）                     │
│  └─ i18n（zh-CN 首版，预留 en-US）           │
├────────────────────────────────────────────┤
│ Tauri 桥接层（invoke / event）              │
│  ├─ entry_list / entry_save / entry_delete │
│  ├─ entry_reorder / settings_get / set     │
│  └─ 面板菜单 / 主界面直达动作               │
├────────────────────────────────────────────┤
│ Rust 侧（src-tauri）                       │
│  ├─ 托盘图标与菜单（双平台行为差异封装）      │
│  ├─ 窗口管理（弹出定位、失焦收起、状态记忆）  │
│  └─ 存储模块（JSON 文件读写，原子写入）       │
└────────────────────────────────────────────┘
```

关键决策：

1. **存储**：本地 JSON 文件，位于系统标准应用数据目录（macOS `~/Library/Application Support/`，Windows `%APPDATA%`），写入采用"写临时文件 + 原子替换"避免损坏；条目与设置、窗口状态分文件存储。
2. **窗口定位**：弹出面板显示前，通过托盘图标在屏幕上的坐标计算窗口位置（macOS 在图标下方、Windows 在任务栏上方），差异封装在 Rust 侧统一函数内。
3. **收起行为**：监听窗口失焦事件自动隐藏面板，两个平台行为一致。
4. **数据倒计时计算**：前端按本地时区计算，纯日期条目按自然日（非 24 小时制），带时刻条目按分钟精度并对齐"下一次发生"（循环条目）。

当前文件与同步约定：

- `entries.json` 使用持久化键 `schema_version: 2`，不再包含条目颜色字段。按本轮已确认决策不提供版本 1 或旧 `color` 字段迁移；读取失败时保留原文件并停止写入。归档仍是可选字段，缺失时视为活动条目；`settings.json` 缺少 `theme` 时跟随系统，缺少 `panelLimit` 时为 6，不自动启用通知或自启。
- 条目与设置使用同一套文件事务：本进程对同一文件串行读取、校验、备份及替换。只有文件不存在才视为首次使用；坏 JSON、未知字段/版本、无权限或无效日期均停止写入。原始文件保留供排查，不自动拿空内容覆盖，也不自动用备份替换原文件。
- 每次替换前，将旧内容写入 `.json.bak`；临时文件写入并同步成功后才重命名。备份失败则取消保存。只保留上一份成功内容；多版本历史、导入导出和恢复界面属于后续阶段。当前锁用于单应用进程内的双窗口操作，不宣称支持多个独立进程同时编辑同一目录。
- `entry_save` 携带编辑起点的 `expectedUpdatedAt`，版本不符或条目已删除时拒绝覆盖；手动排序要求完整活动条目标识集合，避免筛选和并发删除导致错排。
- 保存成功才广播变化；前端用请求序号避免旧读取结果覆盖新结果；重新聚焦刷新数据，可见性变化和共享时钟驱动日期更新。主题在两种窗口同步，关闭监听后清理资源。
- 夏令时：换日使用本地日历递增，未来 7 天包含第 7 天。带时刻的循环以起始日期为下界，恰好到达目标时刻仍显示本次，之后选择下一次；不存在的本地时刻按系统时区顺延，回拨的重复时刻使用较早的一次。界面的确切日期/时刻与有效发生结果同源。此规则在 macOS、Windows 上一致，系统时区数据库差异仍需平台验收。
- 主窗口关闭监听仅为 `config` 授予关闭自身所需的窗口销毁权限，用于确认未保存内容后的关闭，不扩大文件、网络或其他窗口访问权限。

## 12. 风险与注意事项

- **Windows 弹窗定位**：任务栏可能在屏幕四边，托盘图标坐标获取方式与 macOS 不同，M1 中预留手动测试项。
- **macOS 签名**：未签名应用首次打开需右键放行；正式分发是否申请 Apple Developer 签名，在 M5 前另行确认。
- **自然日计算**：跨时区/夏令时场景以"本地日历日"为准，避免出现"差一天"的观感问题。
- **数据格式演进**：0.x 阶段 JSON 结构可能调整，存储模块保留版本字段（当前持久化键为 `schema_version`）以便后续迁移。
- **设计语言迁移**：主窗口、面板与编辑器已共用第 6 节变量；系统/手动主题需继续在两个平台校验，不能以单一界面截图代替完整无障碍验收。

## 13. 设计验收清单

每次界面相关合并前，除工程验收标准外，对照以下清单自查：

### 信息与功能

- [ ] 菜单栏打开后，最重要的条目无需滚动即可看到。
- [ ] 各类型既能快速区分，也共享一致的操作逻辑。
- [ ] 普通条目只填写三个核心信息即可创建。
- [ ] 相对时间与确切日期不会互相矛盾或产生歧义。
- [ ] 设置与高级字段不会干扰高频使用。
- [ ] 面板底部只有带窗口图标的“打开主窗口”，进入完整列表且保护未保存编辑。
- [ ] 近屿摘要与列表无重复条目；搜索、筛选、时线、设置、关于中不显示该摘要。
- [ ] 关于独立于设置；列表页脚仅有条目数量，日常界面无常驻品牌标语。

### 视觉与品牌

- [ ] "时"通过方向、进度、刻度表达，而不是重复使用钟表图案。
- [ ] "屿"通过边界、聚合、曲线与留白表达，而不是场景化插画。
- [ ] 界面在缩小、深色模式和大量条目下仍保持轻盈。
- [ ] 状态颜色具有文字或符号辅助，不单独依赖颜色。
- [ ] 正式图标、菜单栏缩略图与界面图标属于同一几何语言。
- [ ] 三类图标在侧栏、列表、面板与表单中一致，打开窗口不使用太阳图标。
- [ ] 海雾、远屿和潮线不压过正文；深浅色、最小窗口和缩放后仍可读。
- [ ] 时弧进度有可信起终点；等距时线明确不代表时长。

### 交互与无障碍

- [ ] 主要功能可通过键盘完成，焦点顺序自然。
- [ ] 点击、悬停、选中、禁用和错误状态均清楚可辨。
- [ ] 动效短促、有意义，并支持减少动态效果。
- [ ] 空状态提供清楚下一步，不出现空白页面。
- [ ] 背景装饰不拦截操作或进入辅助阅读，高对比度与强制颜色模式下隐藏。
- [ ] 删除、提醒失败和权限关闭都有明确恢复路径。

## 14. 最终设计命题

**时屿不是把时间做成海岛主题，而是把重要时间理解为一座座值得被看见、被靠近、被记住的小岛。**

产品在日常中应像平静水面一样退后；当某个时刻靠近，它才以清楚、温和、准确的方式浮现。这一原则应同时约束功能数量、信息层级、视觉重量、提醒频率和动效强度。
